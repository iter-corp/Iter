================================================================
COIL — INTERVIEW NOTES (FULL PROJECT OVERVIEW)
For online interview with international students (USA)
Languages: English + Turkish
================================================================

1. WHAT IS COIL?
----------------------------------------------------------------
COIL is a cross-platform social community mobile app, similar in
spirit to Instagram + WhatsApp + a small "events" platform, but
built around real-time community interaction and aimed at making
international communication easier (it has a built-in translator).

- Frontend: Flutter (one codebase for iOS, Android, Web, Desktop)
- State management: Riverpod
- Navigation: go_router
- Backend: Firebase (Auth, Firestore, Realtime DB, Cloud
  Functions, Cloud Messaging) + Supabase (for media storage via
  edge functions and signed URLs)
- Live video: Agora RTC Engine
- Translation: Google Cloud Translate API (via Cloud Functions)


2. CORE FEATURES (what the app actually does)
----------------------------------------------------------------
A. AUTHENTICATION
   - Email/password signup + login
   - Google Sign-In
   - Sign in with Apple (iOS)
   - Forgot password / reset
   - Onboarding flow (avatar, bio, gender, location)
   - Account deletion + email blacklist (a deleted account
     cannot re-register with the same email)
   - Admin can remotely delete a user; the app detects this and
     auto-signs them out

B. PROFILES
   - Public profile with avatar, cover photo, bio, gender
   - Followers / following counts (live)
   - User's posts grid
   - Edit profile screen
   - Other-user profile screen with Follow / Unfollow

C. POSTS + HOME FEED
   - Create post with multiple images, caption, public/private
   - Home feed using fan-out to followers' timelines
   - Like / unlike posts (live counters via Cloud Functions)
   - Comments on posts (deleted users still show as "deleted user")
   - Post detail screen + image viewer

D. STORIES (Instagram-style)
   - 24-hour stories (auto-expire via scheduled Cloud Function)
   - Camera capture screen + add-to-story
   - Story viewer with progress bars

E. MESSAGING (1-on-1 + GROUPS)
   - Real-time chat via Firestore streams
   - Inbox + "Requests" tab for non-followers
   - Image messages (via Firebase Storage)
   - Voice messages (record + playback)
   - Reply-to-message (swipe or long-press) — WhatsApp style
   - Message reactions
   - Online presence + typing indicators (Firebase Realtime DB)
   - Unread badges + last-message preview

F. EVENTS
   - Browse events, event detail screen
   - Event registration with admin approve/reject
   - Each approved event auto-creates a group chat
   - Admin can add / kick members; members can leave
   - Inline Accept / Reject buttons in invite notifications

G. NOTIFICATIONS
   - In-app notification feed (likes, comments, follows,
     event invites, messages, etc.)
   - Push notifications via Firebase Cloud Messaging (FCM)
   - Unread badge on bell icon
   - Action buttons (Follow Back, Accept Invite, etc.)

H. LIVE STREAMING
   - Host a live stream (Agora RTC)
   - Join / view live streams from other users
   - Tokens issued securely via Cloud Functions

I. TRANSLATION (the unique selling point for international users)
   - In-app translator screen
   - Translate any text between languages using Google Cloud
     Translate API
   - Save and view translations (saved_translations_screen)

J. ADMIN PANEL
   - Admin role can manage users, events, content
   - Approve/reject event registrations
   - Delete users globally

K. POLLS, REACTIONS, SAVED CONTENT
   - Poll widgets in chats / posts
   - Message reactions bar
   - Saved translations history


3. TECHNICAL ARCHITECTURE (short version)
----------------------------------------------------------------
- Flutter UI layer  ->  Riverpod providers  ->  Service classes
  ->  Firebase / Supabase / Agora SDKs

- Firestore is used for: users, posts, stories, comments, chats,
  messages, notifications, events, live streams.
- Realtime DB is used for: presence (online/offline) and typing
  indicators (lower latency than Firestore).
- Storage: avatars, covers, post images, story media, event
  images, chat attachments.
- Cloud Functions handle: feed fan-out, like counters, follow
  counters, push notifications, story expiry, Agora token
  issuing, translation calls.
- Security rules enforce who can read/write which document.


4. WHY THIS PROJECT IS INTERESTING
----------------------------------------------------------------
- Combines THREE big product areas (social feed, real-time
  chat, live video) in ONE Flutter codebase.
- Built-in translation makes it useful for international
  collaboration — a natural fit for a COIL-style program
  (Collaborative Online International Learning).
- Uses Firebase for cost-efficient scaling on the free Spark
  plan as far as possible (voice messages go through Storage,
  not Blaze-only services).
- Real-time presence + typing on Realtime DB while keeping
  document data on Firestore — best of both worlds.


5. CHALLENGES SOLVED DURING DEVELOPMENT
----------------------------------------------------------------
- A transitive dependency conflict (record_linux 0.7.2 vs
  record_platform_interface 1.5.0) was breaking iOS builds —
  fixed with a dependency_override.
- Admin-deleted users could still log in on other devices —
  added a Firestore listener that signs the user out when
  their user document disappears.
- Self-deleted users could re-register with the same email —
  added an email blacklist check before account creation.
- Google sign-up was being kicked back to login because of a
  reactive signOut firing on a transient null — fixed by only
  firing on a true present-to-missing transition.


6. THE TEAM SPLIT (good to mention if asked)
----------------------------------------------------------------
- Dev A: Authentication, Profile, Posts, Stories, Events
- Dev B: Messaging, Notifications, Follows, Live, Translate
- Shared: Firestore schema, security rules, Cloud Functions repo

HOW TO START THE INTERVIEW — ENGLISH SCRIPT
================================================================

>>> OPENING (30–45 seconds) <<<

"Hi everyone, thank you for joining today. My name is Ahmed,
and I'd like to introduce you to a project I've been working
on called COIL.

COIL is a cross-platform social community app — you can think
of it as a mix between Instagram, WhatsApp, and a small events
platform, but with one big difference: it has a built-in
translator. That makes it really useful for international
communication, which is exactly what a COIL-style collaboration
between students from different countries needs."

>>> WHAT IT DOES (1 minute) <<<

"On the social side, users can create posts with photos and
captions, follow other users, like and comment, and share
24-hour stories — very similar to Instagram.

On the communication side, we have one-on-one chats and group
chats with image messages, voice messages, reply-to-message,
reactions, online presence, and typing indicators — basically
everything you'd expect from a modern messenger.

We also have live video streaming using Agora, an events
section where users can register for events and automatically
join a group chat for that event, and a notifications system
with push notifications."

>>> THE TECH (45 seconds) <<<

"Technically, the whole app is built with Flutter, so it runs
on iOS, Android, Web, and Desktop from a single codebase.
For state management we use Riverpod.

The backend is mostly Firebase: Authentication for sign-in
including Google and Apple, Firestore for the main database,
Realtime Database for presence and typing indicators because
the latency is lower, Cloud Functions for things like feed
fan-out and push notifications, and Cloud Messaging for the
push itself. We use Supabase for media storage, Agora for
the live streaming, and Google Cloud Translate for the
translation feature."

>>> WHY IT MATTERS FOR COIL (30 seconds) <<<

"The reason I think this project fits really well with a COIL
program is the translator. International students from the
USA, Turkey, or anywhere else can chat with each other inside
the app, and the translator helps them get past the language
barrier instantly. The same app gives them the social side,
the messaging side, and the live video side — so a whole
international classroom or community can live inside one app."

>>> CLOSING / INVITE QUESTIONS <<<

"I'm happy to walk you through any part of the app — the code,
the architecture, or a live demo. What would you like to see
first?"
